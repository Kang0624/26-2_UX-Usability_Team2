# 사용자경험및사용성 2조 — 무인 주문 키오스크 3종 비교

교수님 피드백에 따라 서로 다른 메뉴 탐색 구조 3종을 동일한 참가자가 비교하도록 수정한 실험용 키오스크입니다.

## 파일 구성

- `index.html`: GitHub Pages에서 실행하는 단일 HTML 파일. 별도 서버·데이터베이스·외부 라이브러리 불필요.
- `README.md`: 설치·운영·측정 및 데이터 보관 지침.

## 비교 조건

| 조건 | 구조 | 주문 방식 |
|---|---|---|
| A | 계층형 | 카테고리(버거 단품/버거 세트/음료) → 상품 → 옵션 → 장바구니 |
| B | 단계형 | 상품 → 옵션 → 추가 음료 → 주문 확인 순으로 진행 |
| C | 전체 메뉴형 | 처음부터 버거 단품·세트·음료 8개 상품을 같은 목록에 표시하고 직접 선택 → 옵션 → 장바구니 |

- A/B는 기존 시제품의 탐색 방식과 상품·옵션 구성을 유지하고, C를 추가했습니다.
- 모든 조건의 버거·음료 종류, 가격, 옵션, 글꼴·버튼 디자인 및 실험 종료 기준을 일치시키도록 설계했습니다. 탐색 구조는 의도적으로 다릅니다.
- 모든 과업은 결제 없이 **주문 확정**에서 끝납니다.

## GitHub Pages에 반영하기

1. 기존 저장소 `Kang0624/26-2-UX-Usability-Team-2`를 엽니다.
2. 기존 `index.html`과 `README.md`를 백업하거나 GitHub 커밋 기록에서 이전 버전을 확인합니다.
3. **Add file → Upload files**에서 이 패키지의 동일한 이름의 두 파일을 업로드합니다.
4. **Commit changes**를 선택합니다. 저장소의 `main` 브랜치 최상위에 파일이 있어야 합니다.
5. **Settings → Pages**에서 `main` 및 `/(root)` 배포 설정을 확인하고, 기존 GitHub Pages 주소를 새로고침하여 3조건 화면이 나타나는지 확인합니다.
6. 반영되기까지 조금 걸릴 수 있으므로, 브라우저 강력 새로고침을 해 보고 시험 데이터를 다운로드해 확인합니다.

> GitHub 연동을 통한 자동 배포는 하지 않았습니다. 위 업로드 절차가 필요합니다.

## 참가자 배정

- 파일럿: 약 **3명**. 실제 결과를 슬라이드 10에 반영합니다.
- 본실험 계획: **24명**. 동일 참가자가 A·B·C 모두 사용합니다.
- 인터페이스 순서 6가지: `ABC`, `ACB`, `BAC`, `BCA`, `CAB`, `CBA`; 본실험에서는 각 순서에 4명씩 배정합니다.
- 과업 세트 3종(X/Y/Z)을 각 인터페이스에 하나씩 적용합니다. 선택 가능한 과업 세트 순서도 6가지입니다.
- **과업 세트와 인터페이스를 고정 대응하지 마세요.** 둘 다 순서를 바꿀 수 있어야 학습 효과 및 과업 난이도 교란을 줄일 수 있습니다.

### 파일럿 3명 권장 배정 예시

| 참가자 | 메뉴 구조 순서 | 과업 세트 순서 |
|---|---|---|
| P01 | ABC | XYZ |
| P02 | BCA | ZXY |
| P03 | CAB | YZX |

위 구성은 세 구조가 각 평가 순서에 한 번씩 배정되고, 각 구조가 X/Y/Z 과업 세트를 한 번씩 수행하도록 설계한 예시입니다. 참가자 수가 3명뿐이므로 통계적 유의성 판단이 아니라 **기능·절차 점검**에 사용하세요.

## 참가자별 진행 절차

1. 연구자가 참가자 코드와 인터페이스 순서, 과업 세트 순서를 설정합니다. 화면 기록 및 익명 데이터 수집에 대한 동의를 확인합니다.
2. 별도로 준비한 **측정 제외 연습 과업** 1회를 수행하게 합니다. 현재 웹 앱에는 연습 전용 모드가 없으므로 수동으로 진행하세요.
3. 첫 번째 인터페이스에서 주문 과업 3개(T1 단품, T2 옵션 변경, T3 세트)를 수행합니다.
4. 첫 번째 SUS 10문항에 응답합니다.
5. 약 2분간 휴식한 뒤 두 번째 인터페이스에서 과업 3개 → 두 번째 SUS를 진행합니다.
6. 약 2분간 휴식한 뒤 세 번째 인터페이스에서 과업 3개 → 세 번째 SUS를 진행합니다.
7. 연구자가 완료 화면에서 CSV 3종과 JSON 백업을 각각 다운로드합니다.

**한 명당 주문 과업 9건, SUS 설문 3건**을 수집합니다. 휴식 2분은 진행자가 관리합니다. 웹 앱의 휴식 버튼은 2분 경과를 강제하지 않습니다.

## 주문 과업 세트

| 세트 | T1 단품 | T2 옵션 변경 | T3 세트 |
|---|---|---|---|
| X | 불고기버거 단품 | 치즈버거·양파 제외 + 콜라 M | 치킨버거 세트·감자튀김 L·제로콜라 |
| Y | 치킨버거 단품 | 불고기버거·피클 제외 + 제로콜라 M | 치즈버거 세트·감자튀김 L·콜라 |
| Z | 치즈버거 단품 | 치킨버거·양파 제외 + 콜라 M | 불고기버거 세트·감자튀김 L·제로콜라 |

과업 유형을 같게 설계했더라도 난이도 동등성이 확인된 것은 아닙니다. 파일럿 중 특정 세트에서 오류나 지연이 과도한지 확인하세요.
